# Advisory owner private children

| File | Responsibility |
|---|---|
| `canary.rs` | Opaque exact one-shot Phase-1 admission capability. Encrypted Control alone may reconstruct it after the private trust child verifies the exact signed target. Consumption is atomic with the first advisory-owner reservation and grants no Store, witness, provider, route, task, acknowledgement, or serving operation. |
| `canary_trust.rs` | Inactive three-root Ed25519 admission verifier. A scope-unique operator statement binds the private-user commitment, archive/import, maintenance/source/parity/witness facts, and release image; a separately signed image assertion binds that exact statement proof to the same digest. A distinct deployment-observer assertion binds the same proof and image to the constant empty Phase-1 authoritative-mutation set, legacy-only acknowledgements, an exact maintenance-window/deployment/challenge tuple, zero serving replicas, and content-free monitoring/rollback policy commitments. The roots must be nonzero and pairwise distinct, but checked-in production roots are intentionally invalid and there is no caller or signing key. Control persists the runtime facts separately and consumes both admission rows with the exact initial owner reservation. |
| `comparison.rs` | Inactive Phase-1 owner-private exact-R1 recovery, bounded captured-prefix replay, independent pinned-legacy backup/full-parity comparison, atomic exact-live prefix restoration before evidence, repeated source/release/witness authentication, and a one-shot content-free Control settlement bound to the exact released owner. Exact retained-row loading reconciles lost Control responses before new local work. Only after durability, the owner invokes Store's cancellation-owned exact selector/registration retirement; it scrubs the restored queue, exact-reconciles already-retired state, and leaves the legacy connection authoritative. It has no drain publication settlement, acknowledgement, launcher, route, task, provider mutation/list/delete, or serving authority. |
| `abort.rs` | Inactive released-canary abort terminal with one durable row and two explicit loci. Historical resumed-capture commitments remain byte-stable and accept stop/mismatch; released-before-resume uses a separate domain and accepts only stop-requested. Both persist `Prepared` before Store mutation and reach `Aborted` only from a locus-specific opaque retirement/restoration proof or the restart-only exact local-absence proof retaining the user lifecycle. Comparison is exclusive and owner restart is permanently fenced. Pre-owner cleanup remains separate. |
| `abort_reconcile.rs` | Inactive cancellation-owned restart reconciler for an existing `Prepared` abort at either locus. It exact-loads the encrypted-Control operation, obtains only a read-only absence proof from the controller-owned Store while the exact-user lifecycle guard remains held, and completes the same full-tuple `Aborted` CAS. It cannot construct a Store, mutate selectors/providers, or synthesize a missing abort. |
