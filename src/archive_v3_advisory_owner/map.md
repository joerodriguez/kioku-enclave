# Advisory owner private children

| File | Responsibility |
|---|---|
| `canary.rs` | Opaque exact one-shot Phase-1 admission capability. Encrypted Control alone may reconstruct it after the private trust child verifies the exact signed target. Consumption is atomic with the first advisory-owner reservation and grants no Store, witness, provider, route, task, acknowledgement, or serving operation. |
| `canary_trust.rs` | Inactive three-root Ed25519 admission verifier. A scope-unique operator statement binds the private-user commitment, archive/import, maintenance/source/parity/witness facts, and release image; a separately signed image assertion binds that exact statement proof to the same digest. A distinct deployment-observer assertion binds the same proof and image to the constant empty Phase-1 authoritative-mutation set, legacy-only acknowledgements, an exact maintenance-window/deployment/challenge tuple, zero serving replicas, and content-free monitoring/rollback policy commitments. The roots must be nonzero and pairwise distinct, but checked-in production roots are intentionally invalid and there is no caller or signing key. Control persists the runtime facts separately and consumes both admission rows with the exact initial owner reservation. |
| `comparison.rs` | Inactive Phase-1 owner-private exact-R1 recovery, bounded captured-prefix replay, independent pinned-legacy backup/full-parity comparison, atomic exact-live prefix restoration before evidence, repeated source/release/witness authentication, and a one-shot content-free Control settlement bound to the exact released owner. Exact retained-row loading reconciles lost Control responses before new local work. Only after durability, the owner invokes Store's cancellation-owned exact selector/registration retirement; it scrubs the restored queue, exact-reconciles already-retired state, and leaves the legacy connection authoritative. It has no drain publication settlement, acknowledgement, launcher, route, task, provider mutation/list/delete, or serving authority. |
| `abort.rs` | Inactive released-canary abort terminal with one durable row and two explicit loci. Historical resumed-capture commitments remain byte-stable and accept stop/mismatch; released-before-resume uses a separate domain and accepts only stop-requested. Both persist `Prepared` before Store mutation and reach `Aborted` only from a locus-specific opaque retirement/restoration proof or the restart-only exact local-absence proof retaining the user lifecycle. Comparison is exclusive and owner restart is permanently fenced. Pre-owner cleanup remains separate. |
| `abort_reconcile.rs` | Inactive cancellation-owned restart reconciler for an existing `Prepared` abort at either locus. It exact-loads the encrypted-Control operation, obtains only a read-only absence proof from the controller-owned Store while the exact-user lifecycle guard remains held, and completes the same full-tuple `Aborted` CAS. It cannot construct a Store, mutate selectors/providers, or synthesize a missing abort. |
| `controller.rs` | Inactive restart-safe Phase-1 advisory canary controller orchestrating fixed non-configurable `Phase1TmpfsPolicyV1` memory preflight bounds (< 4 GiB and < 25% VM memory), maintenance import execution, canary scope binding, fence deletion, exact-user SQLite VFS capture admission resumption, comparison settlement, and durable Control run progression (`Prepared -> Eligible -> Imported -> Authorized -> OwnerAdmitted -> Retired / Aborted / ManualRequired`). |
| `attestation_challenge.rs` | Inactive nonce-bound Confidential Space claim production: derives the exact claim nonce from the held window's scope-challenge commitment and window ID (never caller-chosen), produces the claim through the hardened https-only WIF-refusing public attestation path via an injectable seam, and packages Debug-opaque zeroizing evidence with a content-free commitment for Control/telemetry. No configuration, credential, route, or startup source exists; the custodian verifier audience arrives only with the reviewed activation change. |
| `live_window_observer.rs` | Inactive live `Phase1WindowObserver` verifying fixed-format, domain-separated, Ed25519-signed deployment-window observations from the pinned deployment-observer trust root, binding window ID, intent, scope challenge, zero-replica digest, sequence, and custodian trusted time to the exact `HeldPhase1Window` before minting the sealed revalidation proof. Verifies against the real pinned deployment-observer root; the operator-supplied `FileSignedWindowObservationSource` consumes signer-produced `payload:signature` hex lines exactly once each, failing closed on exhaustion or malformation. |
| `solo_entry.rs` | Reviewed solo-operator entry for the one-shot Phase-1 advisory canary: strict mandatory-flag parsing (zero values, unknown/duplicate flags, and unreadable evidence refuse), baked-config deployment requirement, pinned three-root authorization verification before any provider construction, durable-ledger archive binding with sealed bind-once, operator observation feed plus /proc/meminfo trusted memory, and content-free stage/commitment output. Reachable only from the pre-serving argv branch, so serving replicas can never carry it. |
| `window.rs` | Inactive non-cloneable `HeldPhase1Window` capability holding verified live maintenance window and zero-replica assertions from a trusted observer, revalidated continuously through import, handoff, and admission. |
| `telemetry.rs` | Structured content-free, commitment-only telemetry recorder emitting privacy-preserving SHA-256 commitments and discrete logarithmic duration buckets across all Phase-1 lifecycle milestones via a bounded non-blocking channel and panic-isolated worker (`catch_unwind`). |
| `monitoring_policy.rs` | Inactive canonical Phase-1 policy byte formats and automatic stop-condition evaluator. `Phase1MonitoringPolicy` and `Phase1RollbackPolicy` parse fixed big-endian `v1` layouts with exact-length, format-tag, non-zero, and range validation (zero comparison mismatches is hard-required), encode back byte-exactly, and produce the domain-separated SHA-256 commitments the signed runtime admission binds as `monitoring_policy_commitment`/`rollback_policy_commitment`; owners, stop commands, and evidence locations appear only as commitments. `Phase1StopConditionEvaluator` is a pure, deterministic, allocation-free, caller-ticked state machine that permanently latches the first crossed bound (comparison mismatch, consecutive/total advisory errors, latency bucket, resident memory, telemetry freshness, non-monotonic ticks) and reports scheduled observation-window completion as a distinct stop reason. Deploying alerts/monitoring and naming on-call/rollback owners remain operator work (C6); no production caller exists in this slice. |
