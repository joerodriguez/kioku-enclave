# map.md — src/ (enclave service)

The entire attested Kioku backend: it terminates TLS and serves OAuth, sync, MCP/REST,
account, quotas, and the summarizer—see [`cp/`](cp/map.md)—alongside authenticated
`410 Gone` tombstones for the retired `/v1/*` query/storage API. Plaintext databases exist only here and in SEV tmpfs, never on
persistent disk; bounded audio, screenshot pixels, transcript/screen text, and metadata
leave the TEE through the documented Vertex inference boundary, while explicitly
configured webhook events use the separate webhook boundary.

| File | Role |
|---|---|
| `main.rs` | Entry point; wires public OAuth, auth-gated control-plane routes (including Cloud Capture v2), legacy `/v1/*`, public health/attestation, and offline ADR-0016 derivation/similarity/evidence/scoring commands; starts media, summarization, and bounded account-deletion reconciliation workers; production serves only through `serve_tls`, while plaintext application HTTP requires a debug build plus `ENCLAVE_TEST_MODE=1`; spawns the isolated ACME :80 listener and renewal loop |
| `tls.rs` | In-enclave rustls termination with a swappable certificate resolver and SHA-256 leaf fingerprint. Production uses ACME; static/generated certificate paths are custom/debug fallback mechanisms, not production launch overrides |
| `acme.rs` | Required production ACME lifecycle: answers HTTP-01 on :80, generates the TLS key in the TEE, persists account/cert/key as context-bound KMS-wrapped state (`acme/tls.json.enc`), blocks boot until a usable cert exists, and hot-swaps renewals |
| [`cp/`](cp/map.md) | **Control plane:** OAuth/DCR, sync, account, MCP + REST, quotas, summarizer, and identity control store |
| `attestation.rs` | Two separated Confidential Space token paths: internal WIF-audience STS exchange for KMS credentials, and public HTTPS-verifier-audience OIDC tokens that can never use the WIF audience |
| `auth.rs` | Legacy caller auth — verifies the control-plane SA ID token before retired `/v1/*` data routes return `410 Gone` |
| `crypto.rs` | KMS/DEK handling plus versioned, context-bound AES-256-GCM v2 blobs. Legacy formats fail closed unless a migration image bakes `ENCLAVE_ALLOW_LEGACY_BLOBS=1` |
| `archive_v3.rs` | **Inactive ADR-0022 foundation:** non-loggable opaque identities; a bounded, caller-buffered archive-key provider resolver that fetches/hashes the exact nominated registry object, passes those same bytes to KMS unwrap, verifies archive/key/monotonic-rotation context in the zeroizing plaintext, and retains object/hash binding; canonical HKDF/AES-GCM archive envelopes with encoded random nonces safe across process restarts; bounded leaf/internal extent Merkle and root codecs; and a cursor-bounded immutable-backend contract with an in-memory test backend. Raw archive DEK/cipher construction is test-only; production-capable root adapters require the resolved cipher. It has no live KMS/GCS client, Store/VFS/witness/route wiring, or write authority until the ADR shadow gates pass. |
| `archive_v3_gcs.rs` | **Inactive ADR-0022 GCS semantic boundary:** async provider-neutral transport and bounded registry-KMS traits plus fakes; strict bounded canonical names/prefixes, permanent archive-wide ID claims committed to the exact key/ciphertext, conditional create with exact read-after-create and explicitly ambiguous lost-success reconciliation, 412 identical/conflict handling, bounded key pagination, and a transport contract requiring verified all-generation deletion. It deliberately has no Store/VFS/witness/route/Firestore/authority/deploy connection or production authority. |
| `archive_v3_gcs_http.rs` | **Inactive concrete GCS REST transport:** caller-supplied narrow bearer tokens only (no metadata-service access), exact percent-encoded JSON API URLs, streamed bounded media/list reads, generation-zero immutable creates, durable reserved→materialized archive-wide claim CAS with lost-success reconciliation, private provider-token pagination behind public key cursors, and bounded all-generation deletion. A disabled soft-delete policy authorizes success only through a separate provider/audit-and-trusted-time drain gate. It is not constructed from env or wired to credential acquisition, a concrete drain proof, Store/VFS/witness/routes/Firestore/authority/deploy, so it performs no live I/O. |
| `archive_v3_journal.rs` | **Inactive ADR-0022 checkpoint/WAL formats:** page-aligned independently encrypted checkpoint chunks, persistent fixed-fanout checkpoint-manifest nodes that stay bounded for a 32-GiB database, and bounded predecessor-linked SQLite WAL segments. One commit may span many objects; the nominated root fixes the exact final reference/generation/count, and chain validation checks root sequence, segment/frame continuity, predecessor hashes, salts, and rolling checksums before accepting the final commit frame. It performs no filesystem, GCS, VFS, witness, recovery, or production-authority I/O. |
| `archive_v3_operation.rs` | **Inactive ADR-0022 mutation ledger:** opaque stable operation IDs; typed-route fingerprints derived from bounded canonical mutation bytes; internally derived bounded inline/entity result digests; an owning 64-operation/1-MiB batch; and an owned SQLite transaction that atomically rolls back domain SQL plus ledger rows on any failure. It is not wired to mutation routes, Store, roots, witness acknowledgement, retention, or GC. |
| `archive_v3_shadow.rs` | **Inactive ADR-0022 WAL-shadow capture state:** a synchronous, fixed-memory mirror for successful underlying WAL writes/truncates/syncs. It emits only checksum-validated complete commit-frame prefixes after successful `xSync`, drops malformed/oversized/queue-saturated shadow generations without affecting the legacy result, and drains captures exactly once. It is not yet registered as a SQLite VFS and performs no filesystem, async, provider, Store, route, recovery, or authority work. |
| `archive_v3_sqlite_vfs.rs` | **Inactive ADR-0022 opt-in SQLite VFS wrapper:** explicitly wraps the SQLite default VFS selected at installation, requires I/O-method version 3 plus its base callbacks, preserves optional shared-memory/fetch fallback, and only after successful WAL `xWrite`/`xTruncate`/`xSync` mirrors bytes to a bounded owner/canonical-path `WalCaptureState`. Owner scopes retire after their main connection closes; at most eight VFS registrations/callback allocations remain through process exit so live SQLite names and raw pointers cannot dangle. Startup never installs it; it has no Store, provider, witness, route, runtime replay, recovery, or authority wiring. Its SQLite oracle tests validate captured WAL framing/replay, post-handle `ATTACH`, and synthetic underlying write/truncate/sync failures for the bundled default VFS, not every platform or custom parent. |
| `archive_v3_witness.rs` | **Inactive ADR-0022 witness/recovery contract:** non-test candidate builders read the exact immutable root back before authenticating/decrypting it, validate `ArchiveRoot` against its complete `ObjectContext`, and require its provider-resolved DEK to remain bound to the exact witness-nominated wrapped registry object/hash/generation; fixed-size content-free records retain the exact current and full predecessor root/registry commitments, durable database-epoch generation, owner/current/next fences, trusted-clock lease expiry, exact provider-authenticated deletion worker/operation identity, and an append-only four-stage deletion evidence chain canonically bound to archive/fence/root/registry/history/provider proof. The in-memory model covers restart-safe fencing, direct legacy→extent shadow migration, extent-authoritative database cutover into a consumed post-cutover state with a derived never-reused epoch and predecessor rollback, post-cutover legacy retirement, monotonic key rotation, deletion-only restart authorization with a separate opaque provider credential and stage proof verified on every step, ordinary-recovery denial after tombstone, and exact-current-candidate lost-success resolution. Persisted IDs are comparison data and never authenticate a caller. It never lists storage prefixes and has no GCS/Firestore, Store/VFS, route, or production-authority wiring. |
| `store.rs` | Per-user encrypted SQLite storage plus encrypted raw-media object access in GCS (load → authenticate/decrypt → mutate → context-bound encrypt → generation-checked persist). A brief actor registry enforces bounded LRU capacity and deletion fences while per-user async locks preserve same-user ordering without holding the registry across SQLite/KMS/GCS/filesystem work; failed eviction preserves the live handle. A per-user content-write barrier admits raw PUTs and checkpoint copies, including owned cancellation-safe provider tasks; deletion atomically closes admission and waits those operations before inventory. It force-flushes dirty local SQLite before remote deletion, so retries rebuild exact media keys from the retained authoritative encrypted DB rather than process-local state. SQLite row changes (including trigger effects), schema changes, and persistent header versions advance a conservative process-local dirty generation; clean saves/evictions skip checkpointing, KMS, encryption, file reads, and GCS PUTs, while detected migrations and failed saves remain dirty. `with_user_read` additionally enforces SQLite `query_only`, and `with_user_mut` is the fail-closed escape hatch for extension/FFI mutations. Before the first overwrite per UTC day, it establishes or verifies one source-generation-pinned, server-side `legacy-recovery/{user_id}/YYYY-MM-DD.db.enc` checkpoint of the exact currently authoritative generation; a process-local verified-day cache removes repeat same-day checks. Startup additionally serially reconciles pre-existing archives with one listing page at a time, explicitly resolves each name's live generation rather than trusting version-list order, and publishes only aggregate readiness/counts; it never activates lifecycle. GCS listings explicitly request at most 1,000 results and use fixed-size fail-closed cursor fingerprints before exact-generation deletion. Account deletion reads each retained `indexes/{user}.db.enc` and `legacy-recovery/{user}/` generation one at a time to inventory DB-referenced unscoped evidence, also reconciles Cloud Capture `raw/{user}/`, and returns a distinct irreversible-gap reason if an exact generation vanishes after listing. This Phase-0 compatibility reader downloads one whole historical snapshot and therefore rejects a listed generation above 512 MiB before download; a future streaming converter must remove that limit. Soft-deleted objects are streamed before and after deletion, preserving the latest provider `hardDeleteTime`, but cannot be manually hard-deleted: pre-existing residue does not prevent best-effort live cleanup, while final residue keeps completion retryable until GCS expires it. A policy-disabled first-page `invalidArgument` is treated as empty, and rollout must disable bucket soft delete. A migration image rewrites legacy user blobs on first open; the legacy whole-snapshot boundary records only process-aggregate storage observations. |
| `storage_observability.rs` | ADR-0022 Phase-0a process-local, unlabeled counters and fixed-bucket histograms for logical/encrypted archive bytes, the pre-checkpoint WAL-length changed-byte proxy, save outcomes/latency, and whole-snapshot durable/WAL-proxy ratio; active aggregates are periodically emitted through existing structured logs without an exporter or user/object/content fields |
| `ingest.rs` | Transactional ingest for transcripts and canonical screenshot provenance/browser dependencies; every nonduplicate screen immediately gets a deterministic observation fallback, while settled episodes later receive one holistic text/metadata Vertex analysis and Mac-computed embeddings retain their model gate and source-key idempotency |
| `search.rs` | Search (SQLite FTS5 + hybrid RRF with vec0 KNN over utterances, screenshots, AND episodes when a query embedding is present). Episode hits are the primary result entity (ADR-0004): relevance-ranked, with FTS snippets + minute_summaries; ADR-0009 excludes `substance=none` before FTS/speaker/hybrid ranking while retaining `low`. Speaker filter (ADR-0006 P3): `SearchRequest.speaker` or inline `speaker:Name` token — utterance `speaker_label` match, episode `participants` via json_each, empty-query browse modes. `search_all` / `search_episodes` are called in-process by `cp::query` |
| `embedding.rs` | **In-enclave query embedding (hybrid search).** candle BERT encoder (`paraphrase-multilingual-MiniLM-L12-v2`, 384-dim, pinned `MODEL_ID`) loaded from `EMBED_MODEL_DIR` (baked into the image). Chunked mean-pooling for long text (10k-char cap). Absent/failed engine → FTS-only, never fatal. Any client that precomputes document embeddings MUST use the identical model and configuration |
| `timeline.rs` | Context / time-range queries; `fetch_context` called in-process by MCP `get_context` |
| `episodes.rs` | v2 episode storage; `upsert_episodes` called in-process by `cp::summarizer`. Holds the ADR-0004 minute-timeline merge and ADR-0009 validated `none → low → normal` upgrade-only substance merge; `write_episode_embedding` stores in-enclave vectors in `vec_episodes`; `purge_episode` deletes an episode + member raw records (FTS/vec cleanup, emptied segments, cross-episode refs) for the user-initiated purge |
| `error.rs` | Error types + HTTP mapping, including structured account-deletion pending reasons and provider retry/deadline metadata |

> Security reminders: don't weaken the attestation/ID-token path; never log decrypted
> content or write plaintext to persistent disk. FTS5 external-content tables MUST use
> the `'delete'` command on update (plain DELETE/UPDATE corrupts the index — see
> PROGRESS.md). Keep this `map.md`, the public API documentation, and downstream `/v1/*`
> clients in sync when modules change.
