# map.md — src/cp/ (in-enclave control plane)

The control plane runs inside the enclave. All
of this runs in the one attested binary; handlers call the data-plane query/storage code
([`../search.rs`](../map.md), `../timeline.rs`, `../episodes.rs`, `../ingest.rs`) in-process
— no HTTP hop. Routes are wired in [`../main.rs`](../map.md).

| File | Role |
|---|---|
| `mod.rs` | `CpConfig` validates image-baked OAuth audiences, allow-list, HTTPS API/browser origins, the optional exact-match Identity Platform reviewer identity, Vertex, and quotas; production JWT secrets come from the KMS-protected control store and the web OAuth secret comes from Secret Manager. `CpState` holds shared stores, verifiers, limiters, and the embedder |
| `tokens.rs` | HS256 JWTs (resource-audience access tokens plus OAuth state/consent/auth-code tokens), PKCE S256, sha256-hex, opaque tokens, UUIDv4. Access verification temporarily accepts the legacy `kioku-mcp` audience during rollout |
| `control_store.rs` | Identity, accounting, and webhook destinations/secrets in the context-bound encrypted SQLite blob `control/control.db.enc` (users, deletion tombstones, OAuth clients/codes, refresh tokens, usage, redacted query log, webhook subscriptions); migration images rewrite legacy encryption on load and remove the superseded Gmail credential table |
| `auth.rs` | End-user Google ID-token verifier (audiences = our OAuth client ids), exact UID/email Google Identity Platform reviewer-token verifier, and `require_auth` middleware → attaches `AuthUser` |
| `cors.rs` | Hand-rolled CORS for the single image-baked HTTPS `WEB_ORIGIN`: answers OPTIONS preflights and stamps `Access-Control-Allow-Origin` only for that exact origin. Layered outside `require_auth` so preflights do not 401; bearer tokens still gate requests |
| `oauth.rs` | OAuth 2.1-style facade + bounded DCR: publishes `WEB_ORIGIN/app/login` as the authorization endpoint, keeps normal sign-in on Google OAuth, accepts the special page's short-lived exact-match reviewer token at `/oauth/reviewer`, and issues resource-bound persisted single-use authorization codes with PKCE and atomic client-bound refresh rotation at `/token`; publishes the read-only `kioku:read` scope |
| `reviewer.rs` | Idempotently seeds only the exact Google-authenticated, namespaced reviewer identity with the synthetic launch, cache-debugging, renewal-link, and French-lesson archive used by public plugin test cases |
| `screen_understanding.rs` | ADR-0014 literal per-screen observation contracts, revision hashing, bounded deterministic fallbacks for complete canonical-screen coverage, and episode-specific semantic ranking independent of image upload |
| `sync.rs` | `/api/sync/batch` joins utterances to segments and validates device-scoped nested browser snapshots plus additive screenshot provenance before transactional ingest; also serves `/status`, `/api/export`, `/api/account` |
| `query.rs` | MCP server `/mcp` with minimized/sanitized screenshot observation fields plus REST search, episode members, feed, authenticated lazy browser-snapshot tabs, purge, screenshot evidence, and webhook routes. Episode members expose every canonical screen with literal observation and episode ranking independent of cloud image presence |
| `mcp_safety.rs` | MCP-only restricted-data boundary: refuses searches targeting payment-card data, health information, government identifiers, or access credentials; redacts matching incidental values recursively after response projection; strips URL query strings/fragments; and fails closed on malformed URLs or oversized strings without modifying the private archive or REST/debugger output |
| `summarizer.rs` | v2 incremental episode summarizer + internal tokio cron (replaces Cloud Scheduler). Open-episode context carries type, participants, the current summary and action items, and the recent timeline so the model extends a shared workflow instead of fragmenting it. Single-pass output includes a concrete, actionable summary, attributed minute gists, exact user-directed actions/resources (including full captured URLs), ADR-0009 substance, and ADR-0010 visual-evidence classification. Guarded one-time historical passes backfill substance and, for normal episodes with screenshot members, visual evidence from stored episode text plus screenshot metadata/OCR only (never image pixels); completion markers are written only after a fully valid pass. After upsert it embeds each episode in-enclave (candle, pinned MODEL_ID → `vec_episodes`, §G.2). Live-tail cursor semantics hold short/empty tails as documented in the module |
| `finalizer.rs` | Episode finalization worker that waits for the summarizer cursor and contributing-device watermarks, builds a bounded chronological log with timestamps, speaker/app/window attribution, exact evidence IDs, and mirrored mic/system utterances deduplicated, then extracts an allow-list of captured URLs, validates structured Gemini evidence references, and stores the canonical actionable brief. Finalization version 3 regenerates each older finalized brief once, preserves its original `finalized_at`, and never replays webhook events; first-time finalization snapshots enabled destinations into the opaque outbox |
| `webhook_worker.rs` | Signed CloudEvents outbox worker for user-configured destinations. It re-fetches each active subscription, builds content-free or explicitly content-bearing finalized-episode events, validates and pins public DNS addresses, refuses redirects, signs the exact body with Standard Webhooks headers, retries bounded transient failures, pauses invalid/gone destinations, and avoids logging endpoint paths or content |
| `vertex.rs` | Vertex Gemini client (`generateContent`) with caller-supplied constrained schemas: full episode output requires summary, action items, `minutes[]`, substance, and visual evidence; historical repairs use compact id/classification schemas. Sends text outside the TEE — documented caveat |
| `limits.rs` | Token-bucket rate limiter + persistent daily ingest quotas. MCP tools use only the volatile rate limiter so their read-only calls do not persist user or query state |
| `isotime.rs` | RFC3339-UTC parse/format/add (no `chrono`; musl-friendly) |

> Identity/accounting writes are low-volume, so the control store persists the whole blob
> per write (fine here, unlike user indexes — see ADR-0002). Keep this `map.md` and the
> public API documentation and downstream clients in sync when routes change.
